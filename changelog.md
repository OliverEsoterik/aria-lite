# Changelog

## [Unreleased] / Planned Architecture Updates

### Database & Pipeline Optimization
- **Intelligent Handling of Delisted/Missing Tickers (`yfinance` errors)**
  - *Decision:* Implement Database Soft-Deletes (Option 1) combined with Cosmetic Logging (Option 3).
  - *Details:* 
    - Add a new `is_active` boolean column to the `dim_entities` table (defaulting to `TRUE`). 
    - When `yfinance` fails to download data for a ticker (e.g., due to delisting or ticker change), the ETL pipeline (`01_fetch_price_data.py`) will automatically flag that ticker by setting `is_active = FALSE` in the database.
    - Future pipeline runs will be optimized to only fetch data for tickers `WHERE is_active = TRUE`. This "self-cleaning" mechanism will prevent the script from wasting API requests on dead tickers day after day.
    - *Terminal Cleanup:* The loud, messy warning outputs generated by `yfinance` will be suppressed from the main terminal console and securely redirected into a background `logs/yfinance_errors.log` file.

### Ranking Persistence & Time-Series Analytics
- **Historical Ranking Data Support**
  - *Decision:* Transition from overwriting ratings to a time-series storage model.
  - *Details:* 
    - Modify the ratings generation logic to include a `snapshot_date` for every record.
    - This enables historical comparisons, allowing the system to track rating changes over time (e.g., comparing today's "STRONG BUY" with yesterday's status).
- **Ranking Momentum Tracking**
  - *Decision:* Implement a "days on ranking" counter.
  - *Details:* 
    - Calculate and store the duration (in days) a specific ticker has maintained its current ranking.
    - This provides insight into the stability of a recommendation.

### Portfolio Management
- **Dynamic Watchlist Configuration**
  - *Decision:* Decouple the `CURRENT_PORTFOLIO` from source code.
  - *Details:*
    - Transition the hardcoded list in `src/etl/03_generate_production_ratings.py` to an environment variable `WATCHLIST`.
    - Implement `os.environ.get("WATCHLIST")` to ingest tickers at runtime as a comma-separated string.
    - This allows for dynamic portfolio updates without modifying the source code.
    - Required workflow updates: Any execution environment (local shell, scripts, CI/CD) must export `WATCHLIST="TICKER1,TICKER2,..."` before running the ETL pipeline.

### System Architecture & Tooling
  - *Decision:* Introduce a dedicated database table for production ratings to decouple generation from consumption.
  - *Details:* 
    - Create a new `fact_ratings` table to store all data generated by `03_generate_production_ratings.py`.
    - Develop `04_fetch_latest_ratings.py` to retrieve information directly from this table instead of querying upstream sources (`yfinance`) during evaluation.
- **CLI Evaluation Utility** (-> we can do this with Makefile, not cli)
  - *Decision:* Build a dedicated make command for on-demand ticker analysis.
  - *Details:* 
    - Create an `evaluate` script that accepts one or multiple tickers (e.g., `"AVGO, MU"`).
    - The tool will query the `fact_ratings` table to provide instant summaries.
- **Workflow Automation (Makefile)**
  - *Decision:* Add targeted `make` commands for individual pipeline stages.
  - *Details:* 
    - Update the `Makefile` to include specific commands for each step, such as triggering the statistics generation script (`02_compute_statistics.py`) independently.
